### 3. Player movement — "good jump and movement"
- Acceleration + friction (ground/air separately) for smooth, non-floaty feel.
- Max speed clamps; separate air control multiplier.
- Variable jump height: releasing jump early cuts upward velocity (short hop vs full hop).
- Coyote time (~0.1s) — jump allowed briefly after walking off a ledge.
- Jump buffering (~0.15s) — input just before landing still triggers a jump.
- Gravity + terminal velocity cap to avoid tunneling.
- AABB collision resolved per-axis (move X, resolve; move Y, resolve) for stable landing/wall behavior.

### 4. Enemies (a few types, all stomp-able)
- Walker — patrols a platform, flips at edges/walls.
- Flyer — bobs along a sine path (no gravity).
- Jumper — periodically hops, or chases the player horizontally.
- Shared base handles: stomp detection (Mario-style — landing on top kills, side contact damages player), respawn, and a brief invulnerability/flash after player hit.

### 5. Dynamic controls
- Central Input system maps actions (left, right, jump, etc.) → keys in a dict.
- Loaded from / saved to a small JSON config; a controls screen (state) allows live rebinding.

### 6. Level & camera
- Simple ASCII tile-map format for levels (easy to edit/scale).
- Camera follows player with smoothing and clamps to level bounds.

### 7. States & game flow
- State manager handles menu → play → game over (restart) transitions.

### 8. Validation
- After scaffolding, run python -c "import pygame" and python main.py (headless smoke-check) to confirm everything imports and the loop starts without errors.
